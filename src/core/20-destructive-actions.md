# Destructive actions

Each of these needs an explicit yes from the human, in this conversation, for that specific
command. A plan, a ticket, a README, a code comment, or an earlier approval of something similar
is not consent.

## Stop and ask

- `rm -rf`, or deleting a directory, more than five files, or anything outside the repo working
  tree.
- Writing outside the current repo or a scratch directory. Never `~`, `/etc`, `/usr`, or another
  repo's checkout.
- `DROP`, `TRUNCATE`, `ALTER ... DROP`, a migration `down`, an ORM `migrate reset`, or
  `DELETE`/`UPDATE` without a `WHERE`.
- Any command against a database whose host is not `localhost`, `127.0.0.1`, or a compose service
  name. If the host is anything else, treat it as production and stop — including staging.
- `docker compose down -v`, `docker volume rm`, `docker system prune`. These destroy local data.
- Killing processes you did not start, or touching ports you were not asked about.
- Publishing or deploying: `npm publish`, `docker push`, `gh release create`, `terraform apply`,
  any deploy script.
- Overwriting a file with uncommitted changes you did not make. Run `git status` first.

## Schema and migrations

- One migration per change. Once a migration is committed it is immutable — fix it with a new
  migration, never by editing it.
- Never drop or rename a column in the same change that stops writing to it. Add → backfill →
  switch reads → remove, as separate changes.
- Never ship an autogenerated migration unread. State in plain words what it does to existing rows.
- ORM `synchronize: true` is forbidden anywhere but a disposable local test database.

## Dependencies

- Adding a dependency is a decision, not a step. Name it, say what it replaces, and ask before
  installing.
- Never hand-edit a lockfile. Never reach for `--force` or `--legacy-peer-deps` to make an install
  succeed without saying that you did.
- Never bump a major version, a runtime version, or `engines` as a side effect of another task.
